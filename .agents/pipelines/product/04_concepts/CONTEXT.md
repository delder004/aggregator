# 04_concepts

Job: Product concepts and taste.

Read the [root context](../CONTEXT.md). Write results under `<run>/04_concepts/`.

## Inputs

Strategic bets and research; existing design references as optional inputs.

## Process

Make each of the three bets tangible in Markdown: a product promise, first-visit narrative, repeat-visit narrative, primary journey, page/content structure and one representative worked experience. Include actual example headlines, sections, interactions or outputs, not only abstract feature names. Label invented examples as illustrative; do not invent vendor facts or user testimony.

For each concept articulate editorial and design principles that have observable consequences: what leads, what is omitted, voice, density, hierarchy, evidence display and what makes the experience memorable. Explain why a person would prefer this experience to their current alternative. Taste is reasoned selection, not a palette or a list of admired sites. Identify tensions such as depth versus scanability and choose a side with reasons. Show what ordinary generic execution would miss. No websites, images or working prototypes are required; the product is a Markdown proposal.

## Outputs

- `output/concepts.md`: selected stage result.
- `handoff.md`: selected input/output links, judgment, unresolved issues and next stage.

## Human check

Continue authorized research without routine approval gates. Clearly distinguish user input from agent proposals; ask only when missing input materially blocks useful work.
