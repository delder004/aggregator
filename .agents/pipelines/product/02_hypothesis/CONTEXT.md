# 02_hypothesis

Job: Hypothesis.

Read the [root context](../CONTEXT.md) and selected preceding handoffs. Write under `<run>/02_hypothesis/`.

## Inputs

User objective and authorization, previous cycle's decision if any, and preceding stage outputs.

## Process

Choose one primary, falsifiable hypothesis for this cycle, with a stable ID. State: for [specific audience in situation], [specific offer/experience] will cause [observable response] because [reason]. Identify the claim type: demand, usefulness, distribution, recurrence, feasibility or growth. Separate those claims rather than treating one as proof of all others.

Explain the strategic belief and why testing this hypothesis matters to the vision. Make the offer tangible in a concise Markdown specimen: promise, representative content/result, journey and editorial/design choices. Compare it with the best substitute and explain why it might be preferred. Show tradeoffs and a credible alternative, without requiring three full concepts in every cycle.

Distinguish long-term vision, potential first release and experiment. Prioritize the assumption whose failure would most change the investment decision. If demand is unproven, normally test problem/offer interest before substantial building; explain any reason a different uncertainty should come first. Name evidence that would disprove the claim. Do not turn the hypothesis into a foregone conclusion or implementation order.

## Outputs

- `output/hypothesis.md`: stage deliverable(s).
- `handoff.md`: inputs, selected outputs, conclusion/status, unresolved issues and next action.

## Human check

Proceed with authorized work. Ask only for consequential missing input, access or authorization required for a concrete next action. A pending experiment must not be described as completed.
