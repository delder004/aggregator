# Product learning loop

Start at [the product pipeline](../../.agents/pipelines/product/CONTEXT.md): **research → hypothesis → experiment → accept/reject**. Four numbered stages and [mirrored runs](../../.agents/runs/README.md) keep context, plans, actual observations and decisions separate.

The final deliverable is one Markdown decision. Experiments may validate demand before substantial building. Execute authorized research/analysis; external experiment actions require applicable authorization. Pending access or insufficient results must not be disguised as validation.

To run: read the root and stage contexts, select the next decisive hypothesis from the previous decision, prepare the smallest credible experiment, execute within authorization, and record what the evidence supports. Resume pending experiments rather than regenerating strategy. Historical proposals remain research inputs, not completed experiments.
